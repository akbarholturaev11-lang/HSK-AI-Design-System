# Data reports

A report should answer a real question with the fewest useful numbers, comparisons and actions. For HSK AI, learning reports summarize **the current learner's verified progress**. Administrator reporting has different permissions, attribution and completeness rules; it must not be treated as the same screen as a learner's personal statistics.

This guidance preserves the original professional information hierarchy, clarity, filtering, incomplete-data handling and accessible presentation while adapting the context to iPhone PWA and native Android.

## Usage and purpose

| Component | Question | Use in HSK AI |
| --- | --- | --- |
| <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary cards</a> | What's the headline? | A verified XP count, current streak, completed lessons or an actual HSK level. |
| <a href="./?path=/docs/design-guidelines-components-data-visualization-progress-charts--docs">Progress charts</a> | How close to a goal? | A lesson count relative to the actual course total; a configured goal only when supported. |
| <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">Distribution charts</a> | How do records spread across categories? | Genuine tracked exercise-result or vocabulary mastery categories, if available. |
| <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend charts</a> | How did a metric change? | Consistently recorded activity across several dates. |
| <a href="./?path=/docs/design-guidelines-components-data-visualization-data-tables--docs">Data tables and lists</a> | Which exact items? | Actual saved lesson, vocabulary or exercise records. |

Only show a component when the real product has the underlying data. A design example is not permission to add a new metric, infer a missing event or fabricate records.

## Making a useful chart

A chart earns its place when it answers the user's question faster than a number or a list. Never chart a single value just because the screen looks empty.

### Number, chart, or table

| Choose | When | HSK AI example |
| --- | --- | --- |
| A number | One verified value answers the question | Recorded streak is 4 days. |
| A chart | A valid trend, meaningful comparison or distribution exists | Activity in several consistently recorded weeks. |
| A table or readable mobile list | The reader needs exact values or actions for individual items | Review an actual saved lesson result. |

### What makes a chart useful

- State **one question or insight per chart**. Don't hide an important conclusion in unlabeled bars.
- Show only the values needed for that question; offer details separately.
- Do not confuse activity quantity with assessment correctness or vocabulary mastery.
- Do not mix lesson starts, successful completions and attempts as one event without a clearly defined mapping.
- For time comparisons, use consistent time zones, date windows, denominators, inclusion rules and event definitions.
- A displayed percentage or count must be reproducible from the authoritative records. Retries and duplicate writes must not inflate totals.
- When a measure has not been fully audited for PWA and Android, disclose that fact; do not claim complete cross-platform coverage.

## Showing growth

A comparison is valid when the earlier and later values measure **the same thing**, with comparable inclusion rules. For a personal learner report, a change may compare the same learner's verified activity at two points in time, or a measure tracked across comparable sets of lessons.

- Define which periods and records are included in both values.
- If the underlying course, HSK level, goal or calculation changed, explain that discontinuity; do not label it growth from an identical baseline.
- Show meaningful numeric change and direction; do not use color or an arrow as the only signal.
- Avoid a congratulatory claim when the metric does not justify it (e.g. doing more attempts does not prove higher mastery).
- A missing earlier period is **not** a zero baseline.

### Choosing the earlier period

When multiple valid historical periods exist, let the learner choose a comparison period only if the product supports it. Label both dates/ranges and update the insight when selection changes. Do not show nonfunctional date filters or preselected periods with no verified records.

## Layouts

### Learner overview

Use HSK AI's existing mobile-first home/profile/progress screen. Present summary first, then relevant progress, then supporting detail or a clear review action. Avoid overwhelming the current lesson with full reporting controls.

### Detailed report

If a metric needs several filters, long histories, many rows, technical definitions or complex explanations, give it a dedicated view. It may have more information density than the learner overview but should still work on narrow PWA and Android screens.

### Administrator analytics

Separate administrative dashboards from learner progress. Use the authorized filter scope, known attribution and platform-coverage rules. If one platform is unaudited or reports partial events, flag the affected metrics rather than falsely aggregating them. Do not reveal personal learner details without proper authorization.

## Page order

1. Short heading and clearly defined reporting scope.
2. Verified summary values that answer the main question.
3. The most useful chart or progress view, if supported.
4. Exact records or an optional route to details.
5. Source period, last successful update or any important coverage limitation when applicable.

Mobile screens may use one column. Preserve the approved bottom navigation, spacing, text scaling, keyboard behavior and safe areas rather than importing desktop teacher-dashboard columns.

### Control scope

Controls affect only the stated dataset below or inside their section. A date filter changing one chart must not silently change unrelated headline statistics. When a filter applies to the entire report, put it above the affected report and say so.

## Containers

Each chart container has one main question, readable labels, optional meaningful controls and a trustworthy state. See <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">Chart container</a>.

## Own page or section

### When data needs its own page or section

Move the report to its own view when there are too many controls, rows or comparisons for an overview. Avoid nested scrolling tables and controls on top of the learning interaction. Keep the user's current context when moving to details.

### Page and section controls

Use only implemented date, category, HSK level and exercise-type filters. Show active selections and provide a working clear or reset route. A detailed report should not expose controls with no supported data.

## Insights and actions

A helpful insight describes the verified data and proposes an action that really exists in HSK AI. For example, if lesson records show unfinished work, a link may return to the actual unfinished lesson. A claim such as "You need to improve pronunciation" requires an actual validated pronunciation assessment, not a guess from chat activity.

Don't invent reminders, scores, awards, difficulty ratings or a "recommended next lesson" that the product doesn't calculate. Explanations and actions must be understandable in the user's selected language.

## States

### Empty states

An empty state explains why data is absent and when it might appear, without implying the learner performed poorly. The empty state must account for the scope of the current filter and actual tracked events.

### Empty container

Keep the section context visible with a short explanation that data is not yet available. Do not replace it with an unlabeled zero.

### Filtered to nothing

Keep the current filters visible and offer a way to clear them. Do not silently expand the date range or change the chosen HSK level.

### Empty state copy

| State | Meaning | Suggested pattern |
| --- | --- | --- |
| Not started | No relevant recorded activity exists | "No lessons recorded yet" with a real start route when available. |
| Not enough data | Too few comparable points to establish a trend | "More recorded periods are needed for a trend". |
| Not supported | This event or metric is not measured on the current platform | Explicitly mark it unavailable rather than 0. |
| Filtered out | No records match the active criteria | "No results for these filters" with a clear action. |

These are meaning examples, not a substitute for the product's current localization catalogue.

### Loading

Use a stable loading state that reflects the layout shape. Known section titles and controls can stay visible while values load. Do not insert fake statistics or permanently freeze a spinner. Keep an existing usable snapshot only when clearly labeled as older data.

### Error

When a request fails, show what couldn't load or save and a real retry when possible. Do not show the error as an empty or zero-value success. Keep previously confirmed totals separate from unverified new data.

### Container errors

A chart-specific failure should not erase unrelated successfully loaded report sections. A global account/session failure may require the broader report to stop showing sensitive data until the account is reverified.

### Partial or processing data

Use explicit partial/processing states. Distinguish "known portion of records", "awaiting aggregation", "source unavailable" and "not yet audited". Admin analytics must disclose platform coverage and avoid treating missing start events as zero starts.

### Not enough data

Do not stretch one or two points into an artificial trend or draw a distribution that suggests a statistically meaningful pattern from a handful of records. Prefer a value, list or concise explanation.

### No access

Keep data from different accounts isolated and respect permissions. On logout/account switching clear learner-specific reports and cached previews that could show another learner's information.

### Too much data

Show a meaningful summary, then let users refine the scope, browse a paginated list or open a dedicated detailed view. Do not place a full desktop-style data grid inside a narrow phone dashboard.

## Accessibility and verification

- Meaning is conveyed through text and values, not color alone.
- Charts have readable summaries and accessible numeric details.
- Missing, zero, partial and failed states are distinct.
- Controls work with touch, keyboard and assistive technology.
- Chinese characters, pinyin and translations are readable at supported text sizes.
- A metric displays its actual units, scope, definition and time basis.
- PWA and Android totals reconcile with authoritative event records; deduplication, aggregation and coverage are checked before a report is called complete.

## Implementation boundary

The HSK AI Design System documents these principles. It must not change production analytics definitions, backfill events, install a chart library or modify the PWA/Android reporting screens automatically. Implementations require comparison against real code, tested data integrity and explicit platform coverage.
