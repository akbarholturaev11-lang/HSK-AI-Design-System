# Data visualization

Data visualization turns verified HSK AI learning data into actionable understanding. A learner should be able to see their completed work, progress toward an actual goal and areas needing practice without guessing how numbers were calculated. Administrative analytics belong to a separate authorized view. These foundations apply to all HSK AI charts on iPhone PWA and Android, but they do not require creating a chart for metrics not yet supported by the product. For how headings and controls are laid out on a page, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs">Data reports</a>. For the components built on these foundations, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#usage-and-purpose">Usage and purpose</a> in Data reports.

## Choosing a chart

Start from the question the reader needs answered, like "How close are we to the goal?" or "How has it changed?" Then pick the simplest form that answers it. To choose a component, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#usage-and-purpose">Usage and purpose</a>. For when a number or a table works better than a chart, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#making-a-useful-chart">Making a useful chart</a>. Both are in Data reports.

People compare position and length more accurately than angle, area, or shade. That's why most of our charts use bars and lines, and why the forms below are avoided.

Bars always start at zero, because readers compare their lengths. Lines can start wherever the data needs, as long as the axis is labeled.

### Forms to avoid

- Pie or donut charts with more than 3 slices. Readers have to compare angles. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">distribution chart</a>.
- 3D charts. The depth distorts length, so equal values look different.
- Gauges or dials. Readers have to compare angles on an arc. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-progress-charts--docs">progress chart</a>.
- Area charts with overlapping series. The shapes hide each other. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">trend chart</a> with lines.

## Anatomy

Use these names for chart parts across all data visualization guidance.

| Part | Purpose | Required |
| --- | --- | --- |
| Section heading (H2) | Names the topic above the chart container, e.g. "Mastery levels" | Yes, in large containers. See <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs#sizes">Sizes</a>. |
| Title (H3) | States the insight, directly above the chart | Yes, except in empty and error states |
| Description | Supporting context, time range, or filters applied | When it adds context |
| Axes and axis labels | Scale and units | Yes, unless values are labeled directly |
| Gridlines | Help estimate values | Optional; keep subtle |
| Data marks | Bars, lines, points, or segments that encode values | Yes |
| Data labels | Exact values on or next to marks | When exact values matter |
| Legend | Maps colors or patterns to series | Only when series can't be labeled directly |
| Tooltip | Details on hover or focus | Optional |
| Annotation | Calls out a notable point, goal, or threshold | Optional |
| Footer | When the data was last successfully updated, or when the value is current | Required for time-sensitive or asynchronously updated reports; unnecessary for a stat whose context is already explicit |

## Color

Chart colors come from the approved HSK AI semantic palette and are chosen by **role**: what the color means. Color supports meaning but never carries it alone. Use the existing PWA/Android theme tokens; do not copy Khan Academy's chart swatches or invent new chart colors. Check contrast in both existing app themes before applying any new pairing.

### Color roles

The role of a color is determined by what the visual communicates. HSK AI retains these professional distinctions while using its **existing approved theme tokens**, not Khan Academy's fixed blue, magenta or gem palette:

| Role | Meaning in HSK AI | Implementation rule |
| --- | --- | --- |
| <span id="progress-and-amounts">Progress and amounts</span> | Lessons completed, current task completion, counted activities or progress toward a genuine goal | Use an approved non-destructive theme color; pair the bar with the actual count/denominator. |
| <span id="categorical">Categorical</span> | Up to four distinct exercise types or other verified categories | Use distinct theme-accessible colors with a visible label for each category. |
| <span id="neutral">Neutral</span> | Background reference, unselected series or an "Other" category | Use HSK AI's neutral theme family. |
| <span id="emphasis">Emphasis</span> | Focus on a relevant value without implying praise or an error | Contrast an emphasized series against subdued neutral comparators. |
| <span id="annotation">Annotation</span> | Goal, threshold, date or reference line | Use legible labels and non-interactive neutral marks. |
| <span id="scores">Scores</span> | Actual verified assessment results, never guessed mastery | Show numerical meaning and thresholds; the error color is not an automatic low-score label. |
| <span id="motivation">Motivation</span> | XP, streaks or earned learning rewards, when actually recorded | Preserve HSK AI's approved reward color semantics; never import Khan Gems. |
| <span id="errors">Errors</span> | A chart loading, processing or query failure, not a poor learning result | Use the separate Critical/error family and a clear error message. |
| <span id="assessment">Assessment</span> | Available quiz/assessment outcomes | Distinguish outcome from percentage of test completed. |
| <span id="mastery">Mastery</span> | Verified vocabulary or learning mastery levels | Use the product's actual level labels, not unimplemented school thresholds. |

Do not assign a new numeric score, grade or color threshold without a validated data definition. The existing HSK AI brand accent, correct-answer green, caution and Critical colors already have distinct roles. Do not repurpose them simply to make a chart colorful.

### Using color roles

<ul>
    <li><Do /> Ensure visible lines, outlines and marks meet the required non-text contrast; do not rely on pale fills alone.</li>
    <li><Do /> Keep each series' color stable across all charts in one context; limit visual clutter to four distinct series where possible.</li>
    <li><Do /> Display counts, units, labels and the applicable denominator alongside relevant progress marks.</li>
    <li><Dont /> Don't make every chart red merely because HSK AI's brand is red. Chart role determines emphasis.</li>
    <li><Dont /> Don't use Critical/error red for a low learner score, a streak break or other valid data.</li>
    <li><Dont /> Don't use a decorative reward color as an error indicator or as an unexplained chart legend.</li>
</ul>

## Typography and numbers

### Type styles

Use HSK AI's existing UI type scale for chart headings, axis labels and explanatory text. Keep Chinese characters and pinyin legible when a learning metric includes vocabulary. Respect user text scaling and the narrowest supported mobile viewport; do not require a desktop font package.

### Number formatting

| Rule | Example |
| --- | --- |
| Round to the precision that matters for the decision | 82%, not 82.37% |
| Use counts for an actual completed task | "12 of 15 lessons completed" |
| Use percentages when comparing differently sized sets | "80% of 15 lessons; 50% of 20 lessons" |
| Pair rate with numerator and denominator when useful | "80% (12 of 15)" |
| Use thousands separators | 1,500, not 1500 |
| Write ordinals on the baseline, not as superscript | 8th, not 8ᵗʰ |
| Abbreviate large numbers | 1.2K, 3.4M |
| Always include actual units | 45 min, 12 lessons, 30 XP |
| Use relative dates within 7 days | "2 days ago," "Due Friday" |
| Use full dates beyond 7 days | Oct 15, 2026 |

<ul>
    <li><Do /> Pair a ratio with a count where the numerator and denominator are known: "80% (12 of 15 lessons)."</li>
    <li><Dont /> Don't overwhelm a learner with oversized raw totals. Prefer a percentage when the underlying count does not aid a decision.</li>
    <li><Dont /> Don't compare differently sized groups using counts alone. Show both proportions or clearly state the denominators.</li>
</ul>

### Missing and zero values

Zero and missing are different and must look different.

- **Zero** is a real value. Show it as `0`.
- **Missing** means no data exists. Show it as `—` and explain why in a tooltip or footnote.
- Give `—` an accessible label. Use the real reason when known, such as "Not started", "Not yet processed", or "No data". Never convert a missing measurement, an unsupported Android event or a failed request into zero.

## Interaction

Expose only interactions implemented in the specific HSK AI screen. A tooltip or chart-to-table switch is not a mandatory new feature; if it is offered, it must work on touch and keyboard.

- **Tooltips** open on hover and on keyboard focus. They add detail but never hold information that's unavailable elsewhere.
- **Hover and focus** states highlight the active mark and mute the others.
- **Legends** can toggle series visibility. Toggling never hides the only series.

## Data context

For asynchronously updated charts show the last successful update time and distinguish "processing", "partially available", "unavailable" and "current". Do not present stale, incomplete or unaudited platform figures as a complete total. When a chart is based on cached data, make the age visible.

## Writing for data

- **Write chart titles as verified insights.** A chart title states a grounded takeaway, such as "12 of 15 lessons completed", not just "Lesson progress". The section heading may still name the topic.
- **Leave the period off titles.** Use sentence case and follow the selected language for HSK AI rather than inserting school-specific wording.
- **Use plain language.** Avoid jargon like "cohort" or "variance" unless the audience expects it.
- **Name users consistently.** Learner-facing screens describe the current learner; admin-facing summaries use the precise user/event scope and protect personal data.
- **Label directly.** Put labels on the marks instead of relying on a legend.

## Accessibility

### Color must not be the only signal

Pair color with direct labels, patterns, shapes, or position. A chart must remain readable in grayscale.

Accessibility must work without assuming a future display setting exists. Use labels, values and accessible summaries immediately; optional display preferences may be added only if actually implemented.

### Marks must meet contrast requirements

Data marks need 3:1 contrast against the background. Light fills meet this through their darker outline (see Fills and outlines). Text in charts follows standard text contrast (4.5:1).

### Provide a text alternative

Every chart needs a short summary of its key takeaway for screen readers. Charts with detailed data also need an accessible data table.

### Support keyboard access

Any information available on hover must also be available on keyboard focus.
