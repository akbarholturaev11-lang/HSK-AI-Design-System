# Progress charts

> **HSK AI scope:** Khan Academy's diagrams show the mechanics of progress bars; they do not define HSK AI's visual style, rewards or school schedule. Only show a bar for a real HSK AI total and an actual verified current value.

<NeutralBadge label="Progress toward a goal" />

Progress charts answer "How close are we to the goal?" A progress bar shows a current value against a goal, and can mark where the group should be by today. Progress means how far along, never how well. An HSK AI progress bar never turns a quiz score or correct-answer rate into completion.

Progress charts sit inside a <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">chart container</a>, large or small.

Use existing HSK AI mobile rendering rather than requiring the source product's chart package.

## <Do /> When to use

| Use when | Example use |
| --- | --- |
| Readers need to see how far along they are toward a goal | Verified lessons completed relative to the actual total, or a real configured XP goal if such a target is supported |
| Readers need to see whether progress is on track for a deadline | Verified activity against a configured, validated learner schedule if it exists |
| Readers need to see how much of a task is done | Recorded completion of a specific supported learning task |

## <Dont /> When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| Readers only need to know ahead or behind, not how far along the goal they are, like "4 lessons completed today" | A <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs#stat-card">stat card</a> | Plain text is faster to read than a chart to decode. Use a bar when seeing how much of the goal is left matters. |
| Showing a score or outcome, like the learner's HSK or vocabulary mastery state | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs#grouped-by-level">Distribution charts</a> grouped by level | A bar reads as how far along, not how well. A full bar would look like success even when scores are low. |
| There's no goal | <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary cards</a> | Progress needs something to measure against. Without a goal, a bar's length means nothing. |
| Readers need to see how progress changed over time | <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend charts</a> | A progress bar shows where things stand today, not how they got there. |

| Part | Rule | Example |
| --- | --- | --- |
| Value and goal | Always as text, not only as bar length | 12 of 15 lessons, if verified |
| Bar | Fills to the current value. Choose colors by role. See <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#color">Color</a>. | |

Actual XP, streak and learning-reward goals (when measured) use the <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#motivation">Motivation</a> color role, not the source product's Gems scheme.

### Expected by today

Expected by today is an optional marker that requires a genuine configured goal, schedule and documented calculation. Do not use the source product's school-day formula as an HSK AI assumption.

If HSK AI has no validated expected-by-today calculation, omit this marker instead of guessing.

Show milestone markers only when HSK AI actually has stored, meaningful milestone dates and values.

## Container

### Large container

For reports. The title states whether the group is ahead of or behind schedule.

| Part | Example |
| --- | --- |
| Section heading | Grade level target |
| Title | 3 skills ahead of schedule |
| Description | 38 of 70 skills · Goal date May 29 |
| Controls | Download |
| Bar | With a labeled expected by today marker, and start and end labels |
| Footer | Updated today, 9:15 AM |

Label the bar's values directly. A legend isn't needed when the value and the marker are labeled.

For dashboards and side panels, like the student dashboard. Keep it to the bar and a few values.

| --- | --- |

<ul>
    <li><Do /> Keep a small container to one bar and up to four values.</li>
    <li><Dont /> Don't add controls, a legend, or an expected by today marker to a small container. If readers need them, use a large container.</li>
</ul>

## Usage guidelines

### Title and description

<ul>
    <li><Do /> State the gap in the title of a large container: "3 skills ahead of schedule," not "Class is ahead of schedule."</li>
    <li><Do /> Show the current value and the goal as text, not only as bar length.</li>
</ul>

### Values

<ul>
    <li><Do /> Show the value as "X of Y," with units: "38 of 70 skills."</li>
    <li><Dont /> Don't fill the bar past 100%. Say "Goal reached" and show the final value.</li>
</ul>

At goal completion, state the verified achieved amount. After a real deadline, show the actual status without manufacturing an expected rate.

### Bars

<ul>
    <li><Do /> Show one kind of progress per container. In Comparing groups, every bar measures the same thing toward the same goal.</li>
    <li><Dont /> Don't mix measures in one container, like skills in one bar and assignments in another.</li>
    <li><Do /> Label the expected by today marker with its value: "Expected by today: 35."</li>
    <li><Do /> When some groups are behind schedule, say so in the title and label each one: "2 of 5 schools are behind schedule." How their bars are colored is still a TODO. See <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#color-roles">Color roles</a>.</li>
    <li><Dont /> Don't show progress as a gauge or dial. Gauges are harder to read and compare, and take more space for the same value.</li>
</ul>

## Variants

### Comparing groups

Use this comparison only for real authorized HSK AI categories sharing one goal definition, not schools or classrooms. The source example illustrates alignment, not a required feature.

Several groups against the same goal, in one large container. Every bar measures the same goal, and one expected by today marker lines up across all of them, so readers can see at a glance who's ahead and who's behind.

| Part | Example |
| --- | --- |
| Section heading | Assignments completed by school |
| Title | 2 of 5 schools are behind schedule |
| Description | Goal: 1,200 assignments per school by May 29 |
| Rows | One per group: name, bar, value, and the gap |
| Expected by today marker | One label above the bars, lined up on every bar |

## States

Empty and error states follow <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>.

If a goal is not configured or the count is not available, show that directly. Do not render a fake zero-progress bar.

## Accessibility

- Every progress chart has a text summary: "38 of 70 skills. Expected by today: 35. 3 skills ahead of schedule."
- Read the value and goal as text: "1,245 of 1,500 gems."
- Announce the expected by today marker with its value: "Expected by today: 35."
- Color is never the only signal. The title or values say whether the group is ahead or behind.

## HSK AI source and measurement constraints

- A lesson total must match the selected HSK level/course version and the same learner; do not silently use an old denominator when the course changes.
- Do not combine correctness, XP, lessons and streak days into one unlabeled bar. A completed lesson is not the same as a passed test.
- Only display milestones, expected daily progress and comparison groups if the corresponding product data and formulas actually exist.
- Retained diagrams (including source school and Gem samples) are **educational illustrations of progress mechanics**, not approved HSK AI branding or features.
