# Progress charts

Progress charts answer **"How close are we to a known goal?"** A bar represents completed quantity relative to an actual total. Progress means **how far along**, not **how well the learner performed**. Preserve this original distinction for HSK AI.

Progress charts belong in a <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">chart container</a>, when a chart is useful. Use existing HSK AI controls and rendering, not a mandatory Khan Academy chart package.

## When to use

| Use when | HSK AI example |
| --- | --- |
| A verified task has a known total | 12 of 15 lessons completed, if both counts exist and refer to the same course version. |
| A supported learning goal has a confirmed target | Actual XP toward a configured goal, only if HSK AI supports that goal. |
| A due date and valid expected trajectory exist | Learner progress compared with a real configured schedule, not a fabricated daily target. |

## When NOT to use

| Situation | Alternative | Reason |
| --- | --- | --- |
| Displaying a quiz score or performance | A score card or meaningful outcome summary | A full completion bar does not mean the answer was correct. |
| No real goal or denominator exists | <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary card</a> | A percentage without a denominator is misleading. |
| Showing changes across several dates | <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend chart</a> | A single bar is not a timeline. |
| Showing levels or categories rather than quantity | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">Distribution chart</a> | Categories must not masquerade as cumulative progress. |

## Chart anatomy

| Part | Rule |
| --- | --- |
| Value and goal | Always visible as text, e.g. "12 of 15 lessons". |
| Bar | Fills proportionally to the confirmed completed quantity; the visible track ends at 100%. |
| Label | Identifies the course, HSK level or explicitly configured learning goal. |
| Expected-by-today marker | Only when a real schedule and documented expected-value calculation exist. |
| Updated status | Say when asynchronous records were last verified, where relevant. |

### Expected by today

This is a computed target, **not a default requirement**. If HSK AI has no user-configured goal, no reliable calendar or no validated formula, omit the marker. Never infer that a learner is behind from a generic school-day calculation.

## Container

### Large container

For a dedicated progress report. Show the verified value, denominator, relevant range, optional genuine target and a clear next step. All quantities must share the same scope and units.

### Small container

For a compact learner-home or profile view: one bar, a short label, current value and goal, with at most a few additional contextual values. Do not import Khan Gems, school challenges, classroom rewards or accessory-unlock artwork.

## Usage guidelines

### Title and description

State progress precisely and in the selected HSK AI language. Prefer **"12 of 15 lessons completed"** to **"Making good progress"** when the former is supported.

### Values

- Keep the source count and goal in the text as well as the bar.
- Do not fill beyond 100%; where extra completed work exists, explain it separately.
- Distinguish missing, pending and uncounted activity from confirmed zero.
- A goal must come from the actual current scope and version: changing the selected HSK level or course must not leave the old denominator in place.

### Bars

- Start at zero and compare like measures only.
- Never mix XP, lesson counts and quiz correctness in one continuous bar.
- Do not create a red danger bar merely because a learner is below a target; use text, appropriate status and the existing semantic roles.
- Text and values must communicate progress without color or animation.

## Variants

### Comparing groups

A comparison is permitted only between real, consistently defined groups (such as separate HSK levels or course sections) with comparable denominators and authorization. The original school-versus-school comparison is not an HSK AI learner requirement. If the groups differ in size, explain or normalize them.

## States

When a goal is absent, show its absence without fabricating a total. When activity is still processing, avoid false completion. After expiry of a deadline, show the recorded state rather than recomputing a misleading percentage. See <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>.

## Accessibility

- Provide a short readable text alternative with actual value, goal and optional expected marker.
- Keep meaningful marks perceivable and their content available by touch, keyboard and screen reader.
- Preserve legibility and context at large text sizes.
- Progress animations must not replace the numeric result and must respect reduced-motion preferences.
