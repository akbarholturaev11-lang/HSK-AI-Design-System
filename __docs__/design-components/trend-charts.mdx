# Trend charts

Trend charts answer **"How has a verified measure changed over time?"** A line connects comparable values from distinct dates or periods. Use them only when HSK AI has enough correctly timestamped and consistently counted records to support a real trend.

Trend charts belong in a <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">chart container</a>. Their layout and rendering adapt to the existing iPhone PWA and Android components, not Khan Academy's school reporting charts or a required web-only chart package.

## When to use

Use when a learner needs to understand the direction and shape of a real recorded metric across **three or more comparable periods**. Examples may include actual recorded activity over time or a supported quiz measure, only where HSK AI verifies the events and the metric definition.

## When NOT to use

| Situation | Alternative | Why |
| --- | --- | --- |
| One data point | <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary card</a> | One value cannot show change. |
| Two points with no future periods planned | Summary card with a verified delta | The numerical change reads faster. |
| A set of unordered lesson types or levels | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">Distribution chart</a> | A line implies time order. |
| Events are incomplete, duplicated or timestamps unreliable | A qualified partial view or no chart | A false trend is worse than no chart. |

## Chart anatomy

| Part | Rule |
| --- | --- |
| Title | States the real change and relevant time span, when established. |
| Time axis | Uses actual dates in order, with uneven gaps shown where applicable. |
| Value axis | States its units and avoids a misleading compressed range. |
| Line | Shows the metric consistently using approved HSK AI chart colors. |
| Data points | Mark periods when useful; disclose unavailable periods as gaps. |
| Context | Explain period selection, verified coverage and last successful update. |

A line's vertical scale need not start at zero, **but** the selected range must not exaggerate small variations. Two different unit types must not share one unexplained axis.

## Container

Use a large chart container where dates, labels and values remain readable. On phones, reduce clutter and let detailed data open in an accessible list. Do not force a desktop legend or chart-and-table switch when not implemented.

## Usage guidelines

### Title and description

Describe what changed, by how much, and since when, **only if the records support the comparison**. A neutral label such as **"Recorded activity by week"** is safer than an invented performance conclusion.

### Time and values

- Compare the same metric and stable calculation rules across periods.
- Leave a gap for a missing or untracked period; never turn it into zero.
- Place date-based points according to their real dates, rather than pretending uneven intervals are equal.
- If one platform does not track the required event, say that coverage is incomplete; don't show combined cross-platform counts as fully audited.
- Ensure repeat events, retries or duplicated writes do not inflate the reported count.

### Lines

- One primary series is preferable; up to four clearly distinct series may be used if necessary.
- Use color roles defined in <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#color">Data visualization</a>.
- Label important series directly when space allows; never communicate series meaning through color alone.
- Do not add confusing overlapping filled areas.
- Label meaningful latest values. Other values must remain accessible by touch/focus or an equivalent readable view.

## Variants

### Comparing groups

Only compare actual, compatible HSK AI learning categories and time windows. Do not create Khan Academy-style school/class averages or a learner leaderboard merely to populate a trend graph.

## States

Differentiate no activity, a confirmed zero, no recorded event, still-processing data and a real error. A missing period is an empty gap, not a collapse to zero. See <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>.

## Accessibility

- Provide a short textual conclusion and values with their units.
- Ensure any focusable point is announced with period and value.
- Do not hide essential information in hover-only interactions on mobile.
- Respect enlarged text and reduced motion.
- A supported chart-to-table switch must preserve precisely the same data scope.
