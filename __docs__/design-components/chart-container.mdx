# Chart container

> **HSK AI scope:** These original figures illustrate chart hierarchy only. For HSK AI, use existing mobile cards, controls and real recorded learning data, not the teacher-dashboard artwork or a mandated chart package.

<NeutralBadge label="Frame for a chart" />

A container holds one chart with its heading, title, controls, and footer. Every distribution chart, trend chart, and progress chart sits inside one. For how containers are laid out on a page, see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs">Data reports</a>.

Use HSK AI's existing PWA and Android rendering and visual components; no specific third-party library is mandated.

## <Do /> When to use

| Use when | Example use |
| --- | --- |
| Showing a distribution chart, trend chart, or progress chart on a report | Recorded lessons, verified practice over time, real learner goal |
| Showing more than one chart on a page | Two charts get two containers, each with its own section heading |

## <Dont /> When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| Showing a complex table, like an actual lesson or vocabulary history with search, sorting, or filters | A <a href="./?path=/docs/design-guidelines-components-data-visualization-data-tables--docs">data table</a> in its own page or section | A complex table needs room for its own controls. A container's controls must fit on one line beside the title. |
| The takeaway is one number with no comparison, like "12 lessons completed" | A <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs#stat-card">stat card</a> | A chart adds nothing when there's nothing to compare. A stat card shows the number at a glance. |
| The data needs more than about three controls | Its own page or section. See <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs">Data reports</a>. | Controls that don't fit on one line crowd the title and wrap. |
| Fitting two charts in one container | Two containers, one chart each | Each container's title states one insight. Two charts compete for one title. |

## Sizes

| Size | Use for | Example |
| --- | --- | --- |
| Large | Reports, where readers study the data | Learning activity over time, if accurately tracked |
| Small | Dashboards and side panels, where readers glance | An actual recorded learner goal, where available |

- A small container holds less: one chart and a few values, with no controls.
- In a small container, the title names the topic, like "Lesson progress." The values carry the insight.

## Anatomy

| Part | Placement | Large | Small |
| --- | --- | --- | --- |
| Section heading (H2) | Above the container | Yes | No |
| Title (H3) | Inside, top left | Yes. States the insight. Not shown in empty and error states. | Yes. Names the topic. |
| Description | Below the title | When it adds context | Context only, like the selected HSK level |
| Controls | Inside, top right, on the same line as the title | Optional | No |
| Chart | Below the title | Yes | Yes |
| Legend | Below the title and description, above the chart | Only when series can't be labeled directly | No |
| Footer | Bottom. When the data was last updated. | Yes | Optional |

A small container needs a freshness indicator when the data may be stale or partial, otherwise avoid redundant metadata.

For the parts of the chart itself, like axes and data labels, see <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#anatomy">Anatomy</a> in Data visualization.

### Headings

The section heading and title each have a different job.

| Part | Purpose | Example |
| --- | --- | --- |
| Section heading (H2) | Names the topic | "Learning activity over time" |
| Title (H3) | States the insight | "Recorded results changed during the available period" |

- The section heading draws the eye down the page and tells readers what the containers below are about.
- The title can have an optional description below it.

## Controls

Controls belong with the chart they affect. On larger screens they may sit beside the title. On narrow phones they may move below it in a readable row; never force unusable one-line desktop placement.

Controls are optional. Add one only when it helps the reader answer the chart's question.

| Control | Use when |
| --- | --- |
| Date filter | The reader may need a different time range |
| View toggle | The same data works as a chart and as a table |
| Download | The reader needs the data outside the product |

When the data needs more than about three controls, it outgrows a container. See <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#own-page-or-section">Own page or section</a> in Data reports.

Only show controls the specific HSK AI screen actually supports.

### Chart and table toggle

The view toggle is optional. It switches the chart to a table of the same data.

<Figure
    src={viewToggleImg}
    alt="A line chart container with the chart and table view toggle outlined at the top right, between the This year date filter and the download button. The chart view is selected."
    caption="The view toggle sits with the other controls, beside the title."
/>

The chart/table switch is optional, and when present both views must use the same scope and totals.

## Accessibility

- Use real heading levels: the section heading is an H2 and the title is an H3. In a small container, the title is the container's heading.
- Give each icon button an accessible name that starts with a verb and includes the chart's topic: "Download growth data," "Show growth as a table."
- The view toggle announces which view is selected.
- Every chart has a short text summary of its takeaway. See <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#accessibility">Accessibility</a> in Data visualization.

## HSK AI implementation and data integrity

- Use existing mobile HSK AI surfaces, readable typography, safe areas and touch targets; do not imitate the source screenshots' styling.
- Do not invent data, force downloads, or create a chart from unsupported metrics. Distinguish recorded zero, no event, still processing, error and stale cached data.
- Chart views and table views of the same records must have matching totals, filters, denominators and date windows; repeated events must not inflate counts.
- Administrative reports require appropriate access and verified per-platform event coverage; personal reports show only the authorized learner's data.
