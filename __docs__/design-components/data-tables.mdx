# Data tables

> **HSK AI application:** these source figures explain table structure only, not a target interface. Replace classroom/teacher examples with actual lesson, vocabulary, practice and authorized analytics records in implementation. On phones, prefer a readable list over a compressed desktop grid.

<NeutralBadge label="Details for each individual or item" />

Data tables answer "Who exactly, and what do I do?" They list an individual, lesson, vocabulary item, recorded practice result or authorized report item with exact values, and can include small visuals such as progress bars and status flags.

Use HSK AI's existing PWA and Android visual components and accessible data controls. The source table framework is a reference, not a required library or style.

## <Do /> When to use

| Use when | Example use |
| --- | --- |
| Readers need to find or act on individuals or items | A learner reviews a recorded lesson or vocabulary item; an authorized administrator inspects a verified report record |
| Readers compare exact values across many columns | Recorded activities with type, date, completion and applicable flags |

## <Dont /> When NOT to use

| Don’t use when | Recommended alternative | Rationale |
| --- | --- | --- |
| The takeaway is one number with no comparison, like "11,033 students assessed" | A <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs#stat-card">stat card</a> | A table makes readers find the number. A stat card shows it at a glance. |
| Readers need to see a pattern or trend | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">Distribution charts</a> or <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend charts</a> | Patterns are hard to spot in rows of numbers. A chart shows them at a glance. |

## Variants

### Basic table

Rows of items with a header row of column labels. Start here, and add summary tabs only when readers need them.

- Put the column readers scan by first, usually the lesson title, vocabulary item, date, or record identifier.
- Write column labels in sentence case, and keep them short: "Completed lessons," not "Total number of lessons that have been completed."

### Table with summary tabs

Tabs above the table show a count for each real, non-overlapping group and filter the table. For example, an available lesson-history view may separate All, Completed and In progress when these states are actually supported.

| Tab part | Example |
| --- | --- |
| Label | Completed |
| Count | 8 lessons |
| Context | 40% of the applicable lesson total |

- The first tab shows the whole group.
- Tab counts add up to the first tab's total, minus any with no result. Say how many: "2 did not complete."
- Percentages use the first tab's total, including any with no result.

## Content

### Names

Use the actual lesson or word label (Hanzi with readable pinyin when applicable). Choose a sorting default appropriate to the data: lesson order, review date or recorded result; do not sort words or lessons as if they were teacher names.

### Column alignment

Align labels and values consistently for the selected language; keep numeric columns scannable. On narrow mobile screens, switch to a readable list rather than forcing a wide table.

### Missing values

Show `—` when there's no data. See <a href="./?path=/docs/design-guidelines-foundations-data-visualization--docs#missing-and-zero-values">Missing and zero values</a>.

## In-cell visuals

| Visual | Use for | Rule | Example |
| --- | --- | --- | --- |
| Progress bar | Completion | Always show the value next to it: 16/20 | TODO |
| Status badge | A row's state | Text plus color | <CompletedBadge /> <InProgressBadge /> |
| Flag | Something that needs action | Icon plus text that says what happened | <WarningFlag label="Rushed 3 times" /> |

Use existing HSK AI progress components only where the value and total are verified.

### Flags

Flags are <a href="./?path=/docs/design-guidelines-components-feedback-badges--docs">badges</a>. Their severity decides the badge.

| Severity | Use when | Badge | Example |
| --- | --- | --- | --- |
| Critical | Something already went wrong, or a deadline passed | <a href="./?path=/docs/design-guidelines-components-feedback-badges--docs#critical-error-status">Critical error</a> | <CriticalFlag label="Overdue" /> <CriticalFlag label="4 didn't finish" /> |
| Warning | Someone may need help, but nothing has failed yet | <a href="./?path=/docs/design-guidelines-components-feedback-badges--docs#warning-status">Warning</a> | <WarningFlag label="3 need help" /> <WarningFlag label="Rushed 3 times" /> |

<ul>
    <li><Do /> Stack up to two flags in a cell, most severe first.</li>
    <li><Do /> Place a flag about a single value, like Overdue, next to that value.</li>
    <li><Dont /> Don't show a flag as a number alone, like "3×." Say what it counts.</li>
    <li><Dont /> Don't use a flag's color without its icon and text.</li>
</ul>

## Interaction

### Sorting

- Make a column sortable when readers need to find the highest, lowest, or a specific item.
- Show a default sort, and mark the sorted column with an arrow.

### Row actions

- Put actions for one row in a "…" menu at the end of the row.
- Add a checkbox column only when there are bulk actions. When rows are selected, show the selected count and the bulk actions above the table.

### Long tables

For a desktop-style table, show no more than 50 rows before pagination; on a mobile screen paginate or progressively load fewer rows as needed for performance.

Pagination must preserve applied filters, selection and a stable item count.

## States

Empty and error states follow <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>. A table that's filtered to nothing keeps its tabs, filters, and header row visible.

## Accessibility

- Mark header cells as column headers, so screen readers read the column name with each value.
- Summary tabs are tabs: arrow keys move between them, and the selected tab is announced.
- Label each checkbox and "…" menu with its row: "Select Unit 3," "Actions for Unit 3."
- Read flags and badges as text, not color.

## HSK AI data integrity and mobile application

- Display a confirmed zero as `0`; missing, unrecorded, processing or unaudited values must be shown distinctly and explained. Never fill gaps with invented activity.
- The row total, filtered total and any export or chart view use the same authoritative population and date range; repeated fetches or duplicate events must not count as new unique rows.
- Do not reveal a different learner's personal history in a learner-facing list or in a stale session after account switching.
- Keep existing accessible sort, row-action, grouped-tab, cell-status, empty/error and keyboard guidance. Provide adequately sized touch targets on both mobile platforms.
- The retained original teacher-table illustrations are **reference examples of structure**, not HSK AI production screens or branding.
