# Summary cards

Summary cards answer **"What's the headline?"** They present an important, verifiable number or state in a readable way, without forcing the user to decode a chart. HSK AI uses its own learner-facing visual style and verified learning data, not Khan Academy's school or district dashboards.

## When to use

| Use when | HSK AI example |
| --- | --- |
| One meaningful value can be understood at a glance | Verified total XP, current streak or lessons completed, where that metric is genuinely available. |
| A small group of values forms a useful overview | Real recorded learning activity, completed lessons and current HSK level. |
| A detail view exists and would help the learner act | A completed-lessons count may link to the actual lesson history, if implemented. |

## When NOT to use

| Situation | Recommended alternative | Rationale |
| --- | --- | --- |
| Showing change across multiple dates | <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend chart</a> | One number cannot show a trend. |
| Showing a spread across categories or ranges | <a href="./?path=/docs/design-guidelines-components-data-visualization-distribution-charts--docs">Distribution chart</a> | A card obscures the distribution. |
| Finding a specific saved record | <a href="./?path=/docs/design-guidelines-components-data-visualization-data-tables--docs">Table or mobile list</a> | Individual items need direct identification and actions. |
| Showing progress toward a known goal | <a href="./?path=/docs/design-guidelines-components-data-visualization-progress-charts--docs">Progress bar</a> | A value without the goal omits how far remains. |
| The metric isn't verified or isn't tracked on that platform | Clearly labeled unavailable state or omission | A fabricated metric undermines trust. |

## Placement

Place summary cards near the start of a relevant learning progress or profile screen, below its heading. They are high-level context and should not displace the primary lesson task. Keep statistics secondary while the learner is actively answering questions or using AI Voice.

## Variants

### Stat card

One card communicates one metric, including its label and value. A row of two to four cards is useful on wider layouts, but **a single informative card is valid** and must not force unrelated numbers onto a mobile screen.

| Part | Requirement | HSK AI example |
| --- | --- | --- |
| Label | Yes; concise and localized | Lessons completed |
| Value | Yes; a verified number, ratio or text state | 12 of 15, if that count is known |
| Unit/period | When the value needs context | Lessons, XP, days, selected date range |
| Context/change | Optional, only if comparable records exist | 2 more than the previous period, if verified |
| Details link | Only when there is a working destination | View completed lessons |

- Use HSK AI's established colors, typography, card surfaces and spacing. Do not import the bright Khan Academy card theme.
- Allow one card per row on narrow phones; use two columns only when values and translated labels remain readable.
- Do not require at least two cards merely because the source design included pairs.
- Include the relevant period or goal in the card or nearby description. Never compare metrics with different periods without saying so.
- Large totals may be abbreviated visually, but exact values must remain available when important.
- A rank must state its actual population; do not invent leaderboards or rank positions.

### Stat cards with a detail view

Only a real destination should get an interactive **View** link. The card need not be clickable as a whole. Maintain accessible link labels, clear focus indication and minimum target areas on PWA and Android.

### Status and directional change

Show increases or decreases with a number and explicit text, never with an arrow or color alone. **A lower metric is not automatically bad**, and a higher metric is not automatically good; interpretation depends on the definition (for example, more recorded mistakes does not necessarily mean worse learning if more practice was completed). Use warning/success badges only for a genuinely meaningful evaluated state.

## States

- **Zero:** show 0 when confirmed.
- **Not recorded:** show a neutral unavailable state, not 0.
- **Processing or incomplete:** indicate that the value is not yet final.
- **Error:** explain the failure and show a retry route when one exists.
- **Different platform coverage:** do not mix unaudited Android data with audited PWA counts as a complete total.
- **Not applicable:** omit an irrelevant card instead of filling it with a made-up value.

For detailed behavior see <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>.

## Accessibility

- Read the label, number and unit together for assistive technology.
- Expose meaningful change as text rather than only as a colored arrow.
- Make any details link independently focusable and specific.
- Allow larger text and long localized labels without clipping.
- Do not rely on card color, motion or decorative rewards to explain data.

## Implementation boundary

These are documentation rules. The availability and definitions of XP, streak, lesson progress, HSK levels and other measures come from HSK AI's real production model; no new server event, metric, target, leaderboard or chart is created simply by adopting this design guideline.
