# Distribution charts

Distribution charts answer **"How are recorded items spread across categories or ranges?"** Bars show counts or percentages. In HSK AI, an item may be a genuine recorded exercise result, lesson state, or vocabulary mastery entry when the underlying data is available. Do not copy Khan Academy's school and classroom statistics.

Distribution charts belong in a <a href="./?path=/docs/design-guidelines-components-data-visualization-chart-container--docs">chart container</a>, using approved HSK AI colors and mobile layouts rather than a mandatory Khan Academy chart dependency.

## When to use

| Use when | HSK AI example |
| --- | --- |
| Learner needs to see distribution across meaningful ranges | Count of recorded items in actual supported mastery categories. |
| Reader needs to distinguish a zero group from a high group | Exercise outcomes split into verified, mutually exclusive categories, if tracked. |
| Real categories must be compared | Counts by available exercise type over a confirmed period. |
| Distribution of one comparable group is available for two periods | Compare the same category rules across both periods without changing ranges. |

## When NOT to use

| Situation | Alternative | Reason |
| --- | --- | --- |
| A single number tells the story | <a href="./?path=/docs/design-guidelines-components-data-visualization-summary-cards--docs">Summary card</a> | Avoid an unnecessary chart. |
| Values change across many dates | <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">Trend chart</a> | Ranges are not a timeline. |
| Exact individual words or lesson records are required | <a href="./?path=/docs/design-guidelines-components-data-visualization-data-tables--docs">Table or mobile list</a> | Grouped bars hide the individual records. |
| Very few items or unsupported categories | Clear text or list | Small samples and invented categories create false patterns. |

## Chart anatomy

| Part | Rule |
| --- | --- |
| Title | States a supported insight; no unsupported claim such as "most learners" on a personal dashboard. |
| Category axis | Meaningful ordered ranges or genuine categories; avoid overlap. |
| Value axis | Count or percentage, **always starts at zero** for a bar chart. |
| Bars | Chosen by role, with enough contrast and readable direct labels. |
| Data labels | Values, units and sample size, when needed. |
| Date / source context | The same reporting period and verified record coverage for all categories. |

## Container

Use a large container when distributions need context or filtering; small mobile summary screens should use a simpler list when bars and labels will not fit.

## Usage guidelines

### Ranges

- Use roughly four to eight meaningful ranges where quantitative grouping is appropriate; a small fixed number of real mastery or HSK categories may use their true defined count instead.
- Ranges must cover all applicable values without overlaps or hidden gaps.
- Keep category boundaries stable between periods. Never redefine ranges to make the latest chart look better.
- Include a clearly identified "none/zero" range where zero is a valid event count.
- Keep an empty category visible when it means a true measured zero. Do not add categories for data that HSK AI does not track.
- When a range has no upper limit, label it explicitly. Never sort ordered numeric ranges by height.

### Title and description

Give the true sample size. If the title says "most", that claim must be supported by the recorded denominator and visible values.

### Values

Use counts when the reader can act on individual items, and percentages when comparing differently sized datasets. State what is being counted. Distinguish different users, lessons, attempts and events; do not mix them under an ambiguous "count". Reconcile group totals with the underlying records.

### Bars

Use vertical bars when labels fit and horizontal bars when long localized labels would otherwise wrap or rotate. Bars share a zero baseline. Highlight only a meaningful comparison, not an arbitrary decorative color. Keep the importance of correct/incorrect lesson feedback separate from genuine system error colors.

## Variants

### Grouped by level

Group records by **actual HSK AI categories** such as implemented mastery levels or HSK level classifications. Labels and thresholds must match the product's actual learning model. Do not import Khan Academy's Beginning/Approaching/Demonstrating score thresholds.

A group count equals the sum of its constituent categories. Label every level in text, not color alone.

### Comparing periods

Compare two real periods with identical category definitions, using the same inclusion rules and units. Clearly state which records are in both samples when a paired comparison is being made. Use a <a href="./?path=/docs/design-guidelines-components-data-visualization-trend-charts--docs">trend chart</a> for three or more time periods.

### Comparing groups

Support only genuine, authorized HSK AI group comparisons that use the same metric definition. Do not create school/class comparisons or expose personal information from unrelated accounts.

## States

- A measured zero remains 0; an unsupported or missing measurement remains unavailable.
- If events are still processing, show that the numbers are partial.
- Missing Android event coverage cannot be quietly merged into a full PWA-plus-Android total.
- On failure, offer a real retry or an explanatory unavailable state.

See <a href="./?path=/docs/design-guidelines-patterns-data-reports--docs#states">Data reports</a>.

## Accessibility

- Provide a short textual summary and an accessible list of categories with values.
- Each bar's accessible label states category, count/rate and unit.
- A category's meaning never depends on color alone.
- Make interaction possible by touch, keyboard and screen reader.
- Do not rotate tiny Chinese labels or truncate the only explanatory text.
